# Repository agent guidance

Read [README.md](./README.md) for this repository's purpose and existing development procedures. These rules govern contributions to ctx itself; they do not change generated project templates or demo fixtures.

## Required independent review

**Major changes require independent Codex and Claude Opus 5.5 reviews before a PR is marked ready or handed to Don for merge** (founder ruling, November 14, 2026). Major means a material effect on architecture; agent-loop behavior, prompts, runtime tools, authority or recovery; listener/customer behavior; security or access; data contracts or migrations; or runtime, deployment or operations. Major plans and operating rules count even when only documentation changes. Routine changes without those major effects follow the organization default: one independent Codex review before founder merge handoff, using the host routing below, appropriate builder checks and required CI. State the classification and rationale in the PR; if material impact is uncertain, use both models.

Each reviewer must be separate from the builder and directing strategist. Each required reviewer inspects the complete diff at the same pinned comparison base and head. Fetch and record the target tip and merge base too. Record each actual model identity, report and findings disposition. An unavailable required model leaves the gate incomplete; do not silently substitute another model or count two Codex reviewers as both models. Only Don can waive a named requirement for a change or an explicitly scoped class; record the ruling and why it applies. This covers new and open unmerged major work, without reopening merged work.

**Routing:** in Codex, use a separate native Codex reviewer subagent with a read-only assignment; in Claude, use `codex exec --sandbox read-only`, never a writable fallback. If the required CLI sandbox is unavailable, report the limitation and leave that review incomplete. For the Opus pass, explicitly select Claude Opus 5.5 in a separate reviewer subagent or Claude invocation. Restrict its tools to the read-only assignment. Instruction and tool-permission boundaries are not operating-system-enforced sandboxes.

Follow the [approved organization review protocol](https://github.com/neuvybe/overlord/blob/f9cb557e8272ea2ad3142e2773ff07b79c6baf18/AGENTS.md#required-independent-pr-review) and [dated ruling](https://github.com/neuvybe/overlord/blob/f9cb557e8272ea2ad3142e2773ff07b79c6baf18/docs/technical/REVIEW_POLICY-2026-11-14.md). Reviewers use disposable detached worktrees at the pinned head, make no source or Git mutations, run no tests/builds, and write reports outside the checkout. Request a recommended fix with every finding and independently verify both the finding and recommendation. Finish all required full passes (both for major changes) before batching corrections; if needed, each required model reviews one focused delta at the same corrected head. If further changes remain necessary, report an incomplete gate and seek direction rather than starting automatic extra rounds. Changed heads or comparison bases need renewed coverage; unrelated target-branch advances alone do not. Retain latest-target integration/CI checks and delta coverage from each required model for material integration changes. Confirm source and review worktrees are clean before retiring review checkouts.

## Existing work and approval boundaries

Use an isolated branch/worktree and PR; preserve unrelated work. Run the checks appropriate to the changed files and satisfy required CI. The review requirement does not replace stronger existing validation or repository-specific push approvals. Never push directly to the default branch. Only Don merges; production changes, deployments and PC operations require his explicit approval. Exclude credentials and environment files from review materials. Use full descriptions in founder-facing text.
