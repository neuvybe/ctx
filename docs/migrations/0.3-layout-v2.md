# Migrating to ctx 0.3: lean layout v2

New `ctx init` scaffolds use layout v2. The fixed core is now README, INDEX,
`context/overview.md`, `context/architecture.md`, `context/caveats.md`, and
ignored `local/CONTINUE.md`. The glossary remains an add-on but is selected by
default for new scaffolds; use `ctx init --without glossary` for the fixed core
alone. Other non-universal concerns moved to opt-in add-ons:

```bash
ctx add --list
ctx add contracts extending
ctx add review
```

Use `--with` during initialization to select those add-ons. A scaffold created
with `--without glossary` can still install it later with `ctx add glossary`.
Large projects can add focused Markdown documents below `context/` and route
them from INDEX's project-owned section. `ctx status` discovers those nested
documents and checks their `ctx:doc` readiness metadata.

Existing layout-v1 and config-less scaffolds remain on their frozen v1 paths.
`ctx update` does not convert layouts, relocate continuation state, or install
optional documents. There is no automatic mode/layout conversion command yet;
adopt v2 by initializing it deliberately and reviewing/migrating project-owned
content.

## Go API notes

- `InitOptions` now includes `Addons`, and `Config` now persists layout,
  template, project, and add-on fields. A nil `InitOptions.Addons` selects the
  defaults; a non-nil empty slice requests the fixed core only. External unkeyed
  literals for either exported struct are source-incompatible; switch to keyed
  fields before upgrading.
- Deprecated `Init(repo, folder)` continues to create the original config-less,
  whole-folder-local v1 layout.
- `TemplateFS()` retains its original frozen-v1 contents for compatibility.
  Use `TemplateFSForLayout(CurrentLayoutVersion)` for the v2 core and
  `AddonTemplateFS(id)` for an optional template tree.
- New integrations can discover catalog entries with `ListAddons`, install them
  with `Add`, and inspect readiness with `Status`.

This is an incompatible pre-1.0 feature release. The release commit must carry
an exact `BREAKING CHANGE:` footer so semantic-release records the migration in
generated notes and applies the repository's pre-1.0 minor-version policy.
