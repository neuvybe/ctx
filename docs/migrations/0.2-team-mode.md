# Migrating to ctx 0.2: team mode by default

Starting with ctx 0.2, a new `ctx init` uses **team mode**. Durable context files
are visible to Git so a repository owner can review, stage, and share them;
machine-local continuation state remains ignored at `local/CONTINUE.md`.

To retain the previous whole-folder-private behavior for a new scaffold, choose
local mode explicitly:

```bash
ctx init --mode local
```

This default change does not convert an existing scaffold. Config-less
scaffolds created by ctx 0.1 remain local, retain root `CONTINUE.md`, and stay
excluded through the repository's common `.git/info/exclude` file.

Go callers that require the original behavior may continue using the deprecated
`Init(repo, folder)` compatibility wrapper. It retains the legacy layout and
whole-folder-local visibility, including safe repository-contained custom paths
accepted by ctx 0.1. New integrations should call `InitWithOptions` and choose
`ModeTeam` or `ModeLocal` explicitly.

ctx does not stage, commit, untrack, or automatically convert context files.
